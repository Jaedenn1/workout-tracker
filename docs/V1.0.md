# Workout Tracker v1.0 — Daily Driver

v1.0 is the reliability release. It keeps the fast local-first Gym Mode and Apple integrations from v0.7–v0.9, but adds a durable browser database, migration path, backup/restore, history corrections, stronger progression rules, and web CI.

## Storage architecture

The durable browser database is now **IndexedDB via Dexie 4.4.5**.

Database: `WorkoutTrackerDB`

Tables:

- `workouts`
- `routines`
- `bodyweight`
- `kv`
- `backups`
- `syncQueue`

The old `workout-tracker:*` localStorage keys remain as a compatibility mirror because the existing Gym, Progress, Health and Watch surfaces already understand them. On first v1.0 launch:

1. `StorageGate` opens IndexedDB before the workout UI mounts.
2. Existing v0.2–v0.9 keys are migrated into IndexedDB.
3. Workout history, routines and bodyweight are normalized into dedicated tables.
4. Future tracked localStorage writes are mirrored into IndexedDB.
5. If an IndexedDB copy exists and a legacy key is missing, the key is restored before the app mounts.

This lets v1.0 harden persistence without rewriting or discarding old workout data.

## Sync queue

Tracked changes also create an IndexedDB sync-queue row. Only the newest unsent change for each logical data key is kept, so rapid weight/reps edits cannot create an unbounded queue.

A successful cloud snapshot clears the queue only after the server accepts the backup. Cloud failure never blocks the local workout.

## Data Center

Route: `/data`

Features:

- IndexedDB counts for workouts, routines and bodyweight.
- Full versioned JSON backup.
- Flat workout-history CSV export.
- Full JSON restore.
- Automatic safety snapshot before restore.
- Manual safety snapshots stored inside IndexedDB.
- Rollback from recent local snapshots.

The portable JSON backup intentionally excludes the private cloud sync key.

## Workout History

Route: `/history`

Features:

- Browse completed workouts.
- Inspect every exercise and set.
- View duration, volume, RIR and estimated 1RM.
- Correct accidental weight/reps/RIR entries.
- Rename a workout.
- Delete an accidental workout.
- Create a safety snapshot automatically before editing or deleting history.
- Recalculate volume, completed-set count, average RIR and set e1RM after corrections.

When a historical workout is edited, old PR labels on that workout are cleared rather than leaving a stale PR claim.

## Progression engine

v1.0 keeps the existing double-progression model but makes decisions more conservative:

- Mixed-load sets keep their set-by-set loading pattern.
- All planned work sets must be completed before automatic load progression.
- Top-of-range sets now need approximately 1.5 average RIR (when RIR is available) before automatic load increase.
- Very high effort or a large rep-range miss holds the load.
- Missing planned sets keeps the load and asks the athlete to complete the prescription first.
- The build-reps state reports the exact number of total reps remaining before the automatic load increase.

## CI

`.github/workflows/web.yml` runs:

- `npm ci`
- TypeScript check
- production Next.js build

The existing Apple CI remains responsible for the iPhone, Live Activity and watchOS source.

## Release boundary

v1.0 does not claim physical iPhone/Apple Watch hardware verification. The native targets were already compiled in v0.9, but actual HealthKit permission, WatchConnectivity, wrist haptics and Dynamic Island behavior still require signing and installation on the user's paired Apple devices.

Cloud sync remains optional. If the Vercel `DATABASE_URL` is unavailable, `/api/sync` stays disabled while IndexedDB, backups and offline workout logging continue normally.
