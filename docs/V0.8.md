# Workout Tracker v0.8 — Native iOS + HealthKit

v0.8 adds the first native Apple layer without turning HealthKit into a dependency of the gym logger.

## Product rule

The PWA remains the local-first source for workout logging. HealthKit access is optional and user-driven.

The browser never requests HealthKit permission. A separate SwiftUI iPhone companion owns all Apple Health authorization, reads, and writes.

## Native companion

Source: `ios/WorkoutTrackerNative`

The companion can:

- Request explicit HealthKit read/write permission.
- Read recent traditional and functional strength workouts.
- Read recent bodyweight in pounds.
- Import a Workout Tracker JSON bridge file.
- Let the user select the exact workouts/bodyweight entries to write.
- Write selected bodyweight samples to HealthKit.
- Write selected strength sessions with `HKWorkoutBuilder`.
- Export a current Apple Health strength/bodyweight snapshot back to JSON.

## HealthKit types

v0.8 requests only the types it currently uses:

- `HKObjectType.workoutType()`
- `HKQuantityTypeIdentifier.bodyMass`

No Health permission is required to use Gym Mode.

## Offline bridge

The bridge is a versioned JSON document so the native layer works before cloud sync is configured.

```json
{
  "version": 1,
  "exportedAt": "2026-08-27T20:00:00.000Z",
  "source": "workout-tracker-web-v0.8",
  "bodyweight": [
    { "id": "weight-1", "recordedAt": "2026-08-27T12:00:00.000Z", "pounds": 145 }
  ],
  "workouts": [
    {
      "id": "workout-1",
      "name": "Leg Day",
      "startedAt": "2026-08-27T17:00:00.000Z",
      "completedAt": "2026-08-27T18:00:00.000Z",
      "durationSeconds": 3600,
      "totalVolume": 19620,
      "completedSets": 18
    }
  ]
}
```

## PWA bridge

Route: `/health`

The page can:

- Export local workout history and bodyweight to the native companion.
- Import a Health snapshot produced by the native companion.
- Keep imported Apple Health snapshots separate from standard workout history.

Imported Health data is stored under:

- `workout-tracker:v0.8:healthkit-imports`

It is intentionally **not** merged into `workout-tracker:v0.2:history`, so imported Health sessions cannot create PRs or change progressive-overload decisions.

## Native project generation

The iOS project is described with XcodeGen so the project configuration stays reviewable in Git.

```bash
cd ios/WorkoutTrackerNative
xcodegen generate
open WorkoutTrackerNative.xcodeproj
```

A physical iPhone install still requires selecting an Apple Developer Team in Xcode for code signing.

## CI

`.github/workflows/ios.yml` generates the Xcode project and performs an unsigned iOS Simulator build on macOS. This catches Swift/HealthKit compile errors without requiring a signing certificate in GitHub.

## PWA updates

- Service-worker cache: `workout-tracker-v0.8`.
- `/health` added to the offline app shell.

## Boundary for v0.8

This release does **not** add Apple Watch workout control, Live Activities, or real-time Watch/iPhone workout mirroring. Those remain later native milestones.
