# Workout Tracker v0.3

v0.3 adds the first training-intelligence layer from the Deep Research blueprint while keeping the app fast and personal.

## Added

- Optional RIR (reps in reserve) entry for every working set.
- Average RIR shown live and stored with finished workouts.
- Estimated 1RM using the Epley formula.
- Live estimated-1RM PR detection against prior saved performance.
- Post-workout PR summary.
- Double-progression style recommendations:
  - increase load when all programmed sets reach the top of the rep range and effort is acceptable;
  - hold load when a set falls below the rep range or average RIR is below 1;
  - otherwise keep the load and beat the prior total reps.
- Per-set suggested loading, so ramped work such as 35 / 40 / 45 lb can progress to 40 / 45 / 50 lb instead of being flattened to one load.
- Post-workout next-session targets with an explanation for each exercise.
- Rest timer controls: -30 seconds, skip, +30 seconds.
- Recent history now shows workout duration plus PR/RIR information.
- v0.2 local history and draft keys are retained for backward compatibility.

## Research references

The feature direction continues to use the project research baseline:

- Hevy / Strong: fast set-entry UX, previous-performance visibility and rest timing.
- Liftin' / Gravl: rule-based progression and double-progression concepts.
- Alpha Progression: RIR-aware progression ideas.
- Workout.cool / Granite: open-source architecture and workout-history concepts.

No commercial source code or protected assets are copied.

## Progression rules in v0.3

For each exercise, the app reads the previous completed sets.

1. **Add load**: every programmed set reaches `repMax`, and average RIR is either not logged or at least 1. The configured increment is added to each prior set load.
2. **Hold**: at least one set is below `repMin`, or average RIR is below 1.
3. **Beat reps**: the workout is inside the rep range but has not earned a load increase yet. Keep the same loads and beat prior total reps.

This is deliberately conservative. Deload automation and more advanced fatigue modeling are deferred.

## Still local-only

Workout drafts and history are still stored in browser localStorage. They do not yet sync between devices. Cross-device persistence remains a later database/sync phase.
